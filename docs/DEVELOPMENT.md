# 탕비실 개발 기준
최종 갱신: 2026-11-06. 현재 결정과 구현만 유지한다. 실행법은 [README](../README.md), 검증 결과와 미검증 사항은 [QA](QA.md), 제품 원칙과 연구 한계는 [FEELCONOMY](FEELCONOMY.md)에 둔다.

## 제품과 공간
회사원이 말없이 함께 쉬는 공용 탕비실이다. 기분에 맞는 행동을 고르고 언제든 멈출 수 있어야 한다. NPC는 보조 역할이며 일반실에는 텍스트·음성 대화가 없다. 출석, 휴식 점수, 관리 숙제, 장시간 체류 보상을 새로 넣지 않는다. 기존 간식 발견 예산은 별도 시스템이다.

메인 방은 16 × 14.4m, 테이블 3개, 좌석 8개다. 오른쪽 잎사귀 문은 승인된 힐링방으로 연결되며 흡연실 문은 닫힌 상태다. 힐링방은 약 10 × 9m, 빈백 4자리·창가 2자리·낮은 테이블 3개·모래 선반·통창·식물로 구성한다. 두 공간을 합쳐 같은 세션의 방문자 6명까지 함께하며 ‘여기’ 인원과 ‘전체’ 인원을 구분한다. 크기와 배치는 현재 구현안이다.

감성적인 실내 3D에 단순한 인물, 세밀한 창밖·가구·가까운 물건을 조합한다. 잘린 세 벽을 내려다보는 미니어처 구도를 기본으로 쓰지 않는다. 통창과 밝은 낮의 색감을 유지하며 의자 다리의 접지, 빈백의 비대칭 곡면·봉제, 잎의 잎맥·가지 연결, 재질의 거칠기와 크기를 실제 화면에서 확인한다. 분위기 이미지가 완성된 실행 자산을 대신하지 않는다.

## 시점과 조작
- 앉기·이동·사물 조작 모두 넓은 1인칭이다. 내 몸은 내 화면에서만 숨기며 동료에게는 보인다. 가로 화면 기준 수평 시야 108도, 수직 시야 42~92도 범위를 사용한다.
- 앉아 있어도 드래그·터치·방향키로 좌우 360도와 상하 시선을 바꾼다. 좌석·위치는 그대로다. 풍경 보기/Home은 창 방향으로 돌린다. 걷기 흔들림과 경로 굴곡별 자동 회전은 없다.
- 빈 바닥을 누르면 실제 경로로 걷고, 빈 의자는 걸어가 앉는다. 사물은 처음 누르면 접근하고, 가까이서 다시 누르거나 곁의 짧은 행동 이름을 누르면 사용한다. 카메라 드래그(5px 초과)의 손떼기는 이동이 아니며, 가구에 가린 바닥은 선택하지 않는다. W/A/S/D는 짧은 보행, 방향키는 시선, Esc는 멈춤이다. ‘갈곳 찾기’는 메뉴 안의 선택적 보조다.
- 목적지 목록·소지품 목록을 여는 동작은 카메라를 바꾸지 않는다. 한 단계의 대표 행동과 내려놓기/그만하기를 분명히 보여준다. 간식은 방 앞의 투명 배경 전경으로 표시한다.
- 이름표는 화면 경계와 다른 이름표를 검사해 온전히 보일 때만 표시한다. 3D 글자는 실제 글자 폭·높이에 맞춘다. 개발용 이전 시점/조명은 `?dev=1&view=3d&camera=map|third|lounge`에서 비교한다.

### 전체 화면과 작은 화면
1280×720, 390×844, 320×568에서 방 캔버스가 화면 전체를 사용한다. 상단의 불투명한 짧은 메뉴와 선택한 물건 곁의 행동만 겹쳐 놓으며 큰 하단 조작판은 없다. 데스크톱에는 소리·도움말·설정·메뉴, 모바일에는 소리·메뉴를 둔다. 메뉴에서 기록/설정/도움말/갈곳 찾기를 연다. 주요 행동은 18px, 48px 이상의 터치 영역을 프로젝트 목표로 삼는다. 이는 실사용 편의성이나 WCAG 전체 준수의 증명이 아니다.

처음 앉으면 내 트레이의 간식에 ‘간식을 눌러보세요’를 붙인다. 아직 꺼내지 않은 포장은 선택용 표시이고 기록/보상은 실제 서버 동작 뒤에만 생긴다. 식품 자체를 누르거나 같은 행동 이름을 누를 수 있다. 레몬파이는 포장을 끌거나 버튼으로 열며, 열린 간식은 탭하거나 버튼으로 먹는다. 끌어서 연 마지막 손떼기는 먹기로 처리하지 않는다. 손에 들 때만 작은 전경과 내려놓기/나누기를 표시한다. 물체 조작의 ‘돌아가기’는 이전 빈 자리 또는 다른 빈 자리까지 실제로 걷는다.

세로 화면은 내 트레이가 잘리지 않도록 좌석의 정면 방향과 조금 낮춘 초기 시선을 사용한다. 이미 돌려 본 방향은 화면 크기를 바꾸거나 앉을 때 초기화하지 않는다. 상세 행동은 물체의 더보기 안에서 선택한다. 새로운 가구·캐릭터·방 추가는 이번 범위가 아니다.

### 렌더링과 소리
숲은 공식 1080p 원본에서 뽑은 1920×960 정지 포스터이며 영상 요청/디코딩을 시작하지 않는다. 바다·불은 별도 영상 설정을 유지한다. 화면 밖·숨긴 탭·모달·TV 시청 중 방의 렌더링과 풍경 재생을 멈춘다. 이름표 배치는 약 8Hz, 움직임 중 그림자 갱신은 최대 10Hz, 정지 중 그림자는 재사용한다. 해상도 상한은 DPR 1.6이며 2048 그림자 자산을 유지한다. 초기 모델 생성과 큰 Three.js 청크는 여전히 후속 측정 대상이다.

파도 로딩은 효과음 전체 로딩과 독립시켰다. 효과음 하나의 실패가 파도 켜기를 실패시키지 않으며, 준비 도중 끄기/TV 열기는 취소로 처리한다. 기본은 무음이고 상단 소리 켜기는 파도와 선택 효과음을 함께 준비한다. 구체적 검수와 제한은 QA에 둔다.

## 풍경과 선택형 공동 TV

창밖은 바다·숲·모닥불 중 선택한다. 방의 추천은 서울 시간 06~18시 바다/숲, 저녁·밤 모닥불이다. 최초 입장 때 정하고 사람이 있는 세션에서는 바뀌지 않는다. 마지막 방문자가 떠난 뒤 60초 이상 비었을 때 다음 입장이 새 세션을 시작한다. 개인 선택과 움직임 끄기는 브라우저에 저장하며, 선택하지 않은 영상은 미리 불러오지 않는다. 촬영/생성 구분·출처·라이선스는 [자산 기록](LANDSCAPE_ASSET.md)을 따른다.

힐링방에 도착해 앉으면 **TV 함께 보기**를 선택할 수 있다. 안내에 동의해 켜기 전에는 YouTube 스크립트·썸네일·플레이어 요청을 하지 않는다. 공식 iframe을 개인정보 보호 강화 도메인으로 불러오고 기본 음소거로 시작한다. 정보 전송이 없다는 뜻은 아니며 외부 연결, Google 개인정보처리방침·YouTube 약관, 실제 게임 저장 항목을 안내한다. 운영자 명칭·연락처를 포함한 정식 서비스 개인정보처리방침은 운영 주체가 확정해야 하는 후속 항목이다.

목록은 빠더너스BDNS·채널십오야·haha ha의 한국 채널 영상 3편이다. 2026-11-06에 공식 원영상의 최근 게시일·공개 누적 조회/좋아요와 실제 삽입 재생을 확인했다. 한국 내 시청자 비중이나 공식 실시간 순위를 뜻하지 않는다. 선정 수치·확인 날짜는 목록과 출처 파일에 남긴다. 직접 다운로드하지 않으며 원본 링크를 제공한다. 공식 플레이어의 로고·조작·광고를 가리지 않는다. 플레이어는 최소 200×200px를 확보하고, 화면 절반 이상 보이는 활성 상태의 플레이어 하나만 자동 재생한다. 게임 조작 소리·기존 파도는 TV 진입 때 멈추고, 그만 보면 이전 파도 선택을 복구한다. TV 소리·자막은 공식 플레이어에서 조절한다.

방에는 세션 ID·영상 ID·목록 버전/순서·시작 기준만 저장한다. 매초 서버 타이머나 재생 위치 polling은 없다. 두 사람이 동시에 다음을 눌러도 세션/버전 비교로 한 편만 넘어간다. 광고·버퍼·개인 일시정지는 공용 시계와 다르므로 매초 seek하거나 다른 사람의 다음 선택으로 현재 영상을 교체하지 않는다. 자연 종료 또는 명시적 **함께 보기로**에서 다음 편에 합류한다. 이는 프레임 단위 동기 재생이 아니다.

**그만 보기**는 내 플레이어만 해제하고 풍경을 복구한다. 새로고침 뒤에도 TV는 자동으로 켜지지 않으며 다시 선택하면 방의 현재 편에 합류한다. 자동 재생 차단은 공식 재생 버튼으로, 외부 연결/영상 오류는 다시 연결·그만 보기로 대응한다. 삭제·삽입 불허·요청 식별 오류가 전체 방을 자동으로 넘기지 않게 했다. 영상 안내·목록은 메뉴에서 다시 읽을 수 있다. 실제 광고 SDK·보상 광고·다른 플랫폼 피드는 이번 범위에 없다.

Node의 `room_media` SQLite 테이블과 CF DO의 방 상태에 같은 공통 규칙(`shared/room-media.mjs`)을 사용한다. TV가 개인 간식/기록을 덮어쓰지 않는다. 정적 영상 Range 목록은 빌드에서 생성하고 기존 Workers Free 구성과 사용자 제한을 유지한다.

플레이어 구현 기준은 [공식 IFrame API](https://developers.google.com/youtube/iframe_api_reference), [필수 기능](https://developers.google.com/youtube/terms/required-minimum-functionality), [개발자 정책](https://developers.google.com/youtube/terms/developer-policies), [개인정보 보호 강화 설명](https://support.google.com/youtube/answer/171780)을 확인했다. 정식 운영 전 정책과 개인정보 안내는 운영 환경에 맞춰 다시 확인한다.

## 힐링방 왕복과 모래
문/목록 선택 → 문 앞까지 걷기 → 문 반응 → 공간 진입 → 예약한 빈 자리까지 걷기 순서다. 이동 취소·목적지 변경·재시도를 지원하며 연결 종료 시 미완료 출입 예약을 해제한다. 같은 방문자·개인 보관함을 유지하고 현재 공간의 아바타·설비·목적지만 보여준다. 공간을 옮기면 이전 조작 소리와 예약 재생을 멈춘다. 파도 선택은 그대로 이어진다.

빈백 눈높이는 1.27m, 창가 의자는 1.48m다. 기본 방향은 바다이며 화면 폭에 따른 자동 회전은 없다. 직접 돌린 시선과 착석 위치는 분리한다. 모래는 선반에서 가져와 자리에 앉아 사용한다. 직접 드래그/돌과 놓을 곳 탭, 선 한 번 긋기/돌 옮기기 버튼, 표면 고르기를 제공한다. 물체 조작 영역은 시선 입력과 분리한다.

개인 표면은 120×80 바이트 높이 정보(저장 문자열 12,800자), 돌 3개 좌표, revision으로 저장한다. 한 요청에 최대 64점을 전송한다. 긴 획은 마지막 점을 이어 64점씩 저장하며 앞선 경로를 단순화하거나 다시 그리지 않는다. 공개 상태에는 손놀이 종류와 짧은 유효 기한만 보내고 개인 ID·선·돌 배치는 보내지 않는다. 접촉 중 약 420ms 간격, 종료 즉시 신호를 보내며 늦게 온 패킷은 동작을 되살리지 않는다. 방 이탈/연결 종료 시 해제하고 유효 기한은 1.1초다. 버튼/Enter/Space 획도 동일한 짧은 소리와 320ms 동작을 만든다. 재시도 영수증은 모래 편집 최근 256개만 보관하며 오래된 revision은 거부한다. 새로고침·내려놓기·왕복 후 같은 상태를 복구한다. 나갈 때 모래를 보관한다는 안내를 보여주고 탕비실로 들어가면 손 점유만 해제한다. 모래를 소유했다는 이유로 탕비실의 간식 행동을 숨기지 않는다.

꽃 선반은 모래 선반과 별도 도착 지점을 가진다. 한 가지 도자기 꽃병에 세 꽃 중 하나를 고르고, 줄기 위치(±0.6)와 기울기(±0.35rad)를 직접 드래그·탭·방향키/버튼으로 조절한다. 선택·배치·revision은 개인 저장이며 다른 사람에게는 꽃 종류와 손 점유만 보인다. 방을 나가면 모래와 꽃병 모두 손 점유를 해제한다. 마지막으로 내려놓은 도구를 주 행동으로 복구하며 이 선택도 저장한다.

차·병·먹던 음식·말랑돌은 왕복해도 유지한다. 힐링방에서 새 간식 꺼내기/원격 시식 받기/나누기는 막고 이미 소유한 음식은 이어 먹는다. 공용 설비는 해당 공간에 실제 도착해야 사용할 수 있다.

## 현재 행동과 저장 규칙
| 대상 | 동작과 중단 | 남는 상태 |
| --- | --- | --- |
| 레몬 샌드파이 | 꺼내기→당기기 또는 버튼으로 열기→세 번 먹기. 열면 먹기 전에도 한 조각 나누기 가능 | 부분 개봉·남은 모양·개인 접시·시식 출처·맛본 기록 |
| 사탕 | 하나 집기→한 번 눌러 포장 열기→먹기 | 기존 부분 개봉을 이어 열기, 소유권·발견 기록 유지 |
| 커피 | 내 컵 놓기→4.5초 추출→가져오기. 추출 중 떠나면 중단 | 중단한 컵 반환, 완성한 커피 보존 |
| 냉장고 | 문 열기→개인 병 하나 꺼내기→닫기. 떠나면 자동 닫기 | 병과 남은 모금, 공용 문/점유 분리 |
| 창가 식물 | 분무기 집기→한 번 분무→내려놓기. 잎 쓸기 선택 | 시듦/관리 점수 없음. 이탈·연결 종료 시 분무기 반환 |
| 말랑돌 | 집기→자리 이동→원하는 부분 누르기→복원→내려놓기/재집기/반납 | 개인 물건 저장. 국소 변형 약 1.55초, 동작 감소 시 짧게 복원 |
| 개인 모래 | 선 긋기·돌 3개 옮기기·표면 고르기·내려놓기·재집기 | 개인 선/돌 보존, 힐링방에 보관, 보상/정답 없음 |
| 개인 꽃병 | 한 송이 고르기·배치·내려놓기·재집기 | 꽃·줄기 위치·기울기·마지막 내려둔 도구 저장. 관리/시듦/수집/보상 없음 |
| 보리차 | 잔 놓기→티백→물 붓기/멈추기→티백 받침→가져오기 | 커피/병과 별도 개인 잔·양·우린 정도. 중간에 가져가거나 이탈해도 보존 |

공용 시식은 제공자의 개인 음식을 줄이지 않는다. 포장이 열려 있고 먹을 양이 남아 있어야 새로 나눌 수 있으며, 다 먹은 음식/시식 조각으로 새 접시를 만들 수 없다. 받음과 실제 맛봄을 구분하고 같은 시식의 중복 수령을 막는다. 기존 발견 예산은 기본 40, 첫 발견 +10이며 나누기만으로 발견/예산을 주지 않는다. 구매·장기 경제·새 휴식 보상은 미구현이다.

손이 차면 버튼에 ‘현재 물건 내려놓고 …’를 명시한다. 서버도 교체 의사를 검사한다. 개인 ID는 공개 스냅샷에 내보내지 않는다. 도착·소유권·공용 설비 예약을 검사하고 같은 요청의 재시도는 중복 생성·먹기·보상을 일으키지 않는다. 빠른 분무/말랑돌 재입력은 추가 소리·입자나 오류창을 쌓지 않는다.

차의 물 붓기는 최대 약 3초, 색 번짐은 시간에 따라 진행하지만 강제 대기는 없다. 중지·즉시 가져오기·이탈 모두 현재 양을 보존한다. 마지막 연결이 종료되면 조작을 멈추고 개인 잔을 반환한다. 공용 점유에는 기존 연결 유예가 적용된다.

## 구현 구조와 운영
React 18·TypeScript·Vite 7·Three.js를 사용한다. 로컬은 Node.js 24의 SQLite와 SSE, Cloudflare 테스트 배포는 Workers Static Assets·SQLite Durable Objects·휴면 WebSocket을 사용한다. `server/game-store.mjs`와 `server/room-view.mjs`의 저장·행동 검증·공개 상태 규칙을 두 서버가 공유한다. `shared/space.mjs`의 가구·좌표·경로를 서버와 화면이 공유한다. `shared/rest.mjs`는 손 점유와 시간 기반 차 상태를 계산하고, `server/rest-activities.mjs`는 조작·소유권·해제를 담당한다.

개인 물건은 `pantry_items` JSON에 추가 필드와 기본값을 보충한다. SQLite의 기존 접시·앨범·시식 기록은 삭제하지 않는다. 과거 수령을 실제 맛봄으로 추정해 소급하지 않는다. 데이터는 `data/pantry.sqlite`, 방문자 토큰은 브라우저, 서버에는 토큰 해시만 보관한다. 브라우저 데이터 삭제 후 계정 복구/기기 간 동기화는 없다. 실행·LAN 접속·DB 백업 주의는 README를 따른다.

Cloudflare는 방마다 `PantryRoom`, 개인 기록마다 `PantryVisitor`, 입장 제한용 고정 8개 `PantryGate`로 분리한다. 방의 개인 변경과 저장 대기 기록을 함께 확정하고 개인 객체에 버전 순서로 저장한 뒤 성공을 응답한다. 방 이동은 이전 방의 저장·쓰기 권한 반환 후 진행한다. 연결은 휴면 WebSocket과 자동 ping 응답을 사용하며 서버 반복 타이머는 없다. 이동·음료 완료·퇴장 유예·제한된 저장 재시도만 알람으로 처리한다. 새 저장소는 로컬 Node DB와 분리되며 기존 기록을 업로드하지 않는다. 새 설정은 `wrangler.pantry.jsonc`, 무료 한도·제한 값·검수 순서는 README를 따른다.

### 바다와 소리
창밖은 생성 원경의 수면을 움직인 24초 WebM/MP4 시네마그래프다. 실사 촬영 영상이나 GIF가 아니다. 실패 시 정지 원경으로 이어가며 동작 감소, 비활성 탭, 모달, 화면 밖 중단을 지원한다. 단일 원경 평면의 깊이별 시차 한계는 남아 있다. 제작/원본 기록은 [LANDSCAPE_ASSET](LANDSCAPE_ASSET.md)에 보존한다.

파도는 44초 실녹음 루프이며 영상과 별도로 켜고 끈다. 전체 기본 무음, 씹는 소리 기본 끄기, 개별 음량과 동료 소리 선택을 유지한다. 실녹음 편집을 우선하고 전체 6개/동료 2개 소리 상한을 둔다. 설정에서 무음/파도만/파도와 행동을 비교한다. 모래는 CC0 마찰 3구간(각 0.52초)과 돌 0.25초 구간을 사용한다. 드래그는 최대 두 개의 짧은 grain을 겹치고 속도에 따른 gain/rate를 제한한다. 손을 떼면 40ms fade, 움직임이 끊기면 100ms 이내 종료를 시작한다. 탭 비활성/연결 종료/방 전환도 정리한다. 말랑돌·잎 쓸기에는 가상 효과음을 새로 붙이지 않았다. 파일별 제작자·라이선스·링크·편집·해시는 `src/assets/audio/*CREDITS*`, `src/assets/environments/*CREDITS*`와 인접 JSON에 둔다. 수치 검사와 실제 청취 평가를 구분한다.

### 남아 있는 구버전 운영 파일
현재 게임은 Node 서버 또는 새 Cloudflare Workers/DO 구성이 필요하다. 기존 Cloudflare Pages 정적 배포만으로 새 실시간 API가 실행되지는 않는다. `functions/api/chat.ts`, `supabase/schema.sql`, `wrangler.toml`, 이전 검증 스크립트는 구버전 호환 파일이며 새 서버의 설정법으로 혼동하지 않는다. 새 Worker `tangbisil-playtest`는 기존 Pages와 별도로 배포한다.

- 구버전 NPC 키 `ANTHROPIC_API_KEY`는 서버 비밀 값(.dev.vars/호스트 secret)이며 VITE 변수나 브라우저에 넣지 않는다. 기존 Functions의 `nodejs_compat`·`BUDGET_KV` 설정을 배포 시 확인한다. KV가 없으면 현재 구버전 코드는 예산 제한 없이 경고 후 통과한다.
- 구버전 Supabase를 운용할 경우 최신 저장소 스키마의 재실행 보호와 RLS를 사용한다. 예전 publication 중복 추가가 트랜잭션을 실패시킬 수 있으며, 모든 삭제를 허용하던 `public_all` 정책을 되살리지 않는다. 컵 정리는 `prune_old_cups`로 제한한다. VITE_SUPABASE 값은 빌드 시 공개 클라이언트 설정이다.
- `verify:deploy`는 기존 원격 NPC API를 실제 호출할 수 있고, `verify:online`은 기존 Supabase를 대상으로 한다. 현재 로컬 게임의 일반 검증에 실행하지 않는다. 구버전 가격표·담배 의식·합성 소리·연속 출석은 새 제품의 약속으로 이어받지 않는다.

## 다음 순서와 미확정 사항
1. 메인 방의 첫 3분, 발견·조작·중단을 실제 첫 사용자 5~8명에게 관찰한다. 실물 모바일의 성능·발열·Safari·화면 확대, 헤드폰 음색/반복 피로를 별도 확인한다.
2. 검토된 불편을 고친 뒤 간식 하나를 완성한다. 간식 풀은 안정된 종류 ID와 버전을 갖고 교체해도 이미 소유한 음식·부분 개봉·발견 기록을 바꾸지 않도록 설계한다. 교체 주기·추첨·희소성·운영 도구는 미확정이다.
3. 힐링방은 이번 승인 범위로 구현했다. 다른 방은 별도로 승인할 때 진행한다. 흡연실 문은 유지하고, 흡연실에서는 선택적으로 사념을 남기는 방향이다. 실시간 대화와 구분하며 일반실에 글·미리보기·새 글 배지를 가져오지 않는다. 글 길이·보관/만료·신고/숨김/본인 삭제·운영 정책은 미확정이다. 글을 보려고 흡연을 강요하지 않는다. Space 길게 누르기→놓으며 내쉬기는 후속 후보이며 글 입력과 충돌하지 않아야 한다.
4. 힐링방의 실제 사용자 편안함·동료와 풍경의 구도를 검토한다. 꽃 한 송이와 모래 실녹음은 이번 범위로 연결했다. 청취/실물폰/첫 사용자 관찰 후 조정하며 추가 피젯/ASMR은 별도 범위로 남긴다.

무료 공개 테스트를 위한 배포 구성과 로컬 런타임 검증을 마쳤다. 공개 HTTPS에서 두 방문자·재배포 후 기록·실물폰을 별도 검수하며, 계정 복구·백업/보존 정책·운영 관리·부하 검증을 마치기 전 정식 서비스 준비가 완료됐다고 보지 않는다. 유료 전환이 필요한 변경은 먼저 사용자에게 알린다.

## Git 준비 상태
작업 브랜치는 `codex/shared-lemon-pie`, 기존 원격은 `github.com/diaplus97/tangbisil`이다. 기존 main을 덮어쓰거나 이력을 초기화하지 않는다. 구현/검증 후 현재 브랜치에 기록하며 원격 인증/업로드는 별도로 확인한다. `data/`(SQLite·방문자·원음), `test-results/`, 참고 자료·실행 로그·`.env`/`.dev.vars`는 제외한다. 기존 추적 `.env.production`에는 공개 Supabase URL과 publishable 클라이언트 키만 있고 이번 변경에는 포함하지 않는다. 비밀 값 패턴 검사는 현재 파일에 대한 보조 검사이며 이력 전체 보안 감사를 뜻하지 않는다.

## 참고와 변경 이력
시점 판단에는 [Denisova & Cairns, CHI 2015](https://www-users.york.ac.uk/~pc530/pubs/Denisova_CHI2015.pdf)를 참고했지만 Skyrim 연구가 휴식 게임의 최적 시점을 증명하지는 않는다. [점진적 공개](https://www.nngroup.com/articles/progressive-disclosure/)는 첫 행동을 단순하게 하는 참고다. [SANSA](https://sansatemple.com/)는 말없이 함께 머무르는 방향과 세밀한 환경의 참고이며 자산·제작 기술을 복제한 것은 아니다.

- 11-04: 공유 레몬파이·저장·나눔 기반, 바다 정면 실내와 가구/빛/재질 개선.
- 11-05: 공간 확장, 사탕·커피·냉장고, 반복 바다/파도. 전체 보기·낮은 3인칭을 비교한 후 사용자 피드백에 따라 자유로운 1인칭으로 대체.
- 11-06: 식물·말랑돌·차, 명시적 소지품 교체. 모바일 높이/목록/입력 안내/차 근접 구도 수정. 중복 문서 통합, 구버전 README의 유효 운영 주의만 이관.

## 문서 유지 원칙
작업마다 새 MD를 만들지 않는다. README는 실행/사용, 이 문서는 현재 결정/구조/다음 범위, QA는 유효한 검사/증거/한계, FEELCONOMY는 근거/해석, LANDSCAPE_ASSET은 자산 출처를 맡는다. 바뀐 결정은 본문을 교체하고 이력 한두 줄만 남긴다. 반복된 캡처·검사 서술과 폐기된 계획은 합치거나 삭제하고 링크도 고친다. 고유한 운영 정보와 자산 제작자·라이선스는 삭제 전에 이관하거나 원본에 보존한다.
