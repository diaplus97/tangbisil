## 흡연실 자유 입력·원형 좌석·흡연 동작 (2026-11-12)

- 기존 한마디가 화면 아래에 놓이던 원인은 도트 전용 배치 CSS의 범위 누락이었다. 이 수정은 유지하면서 새 80자 자유 입력·반투명 카드·공감으로 교체했다. 390×844·320×568·1280×720 두 방문자로 입력→상대 표시→공감, 한글 조합 중 Enter 보호, 입력 중 WASD/Space/방향키 차단, Escape 닫기와 포커스 복원을 확인했다. 도트 화면의 자유 입력·공감도 WebGL 없이 통과했다.
- 여섯 방문자가 80자까지 전송했을 때 두 장 이상의 카드는 상대 얼굴을 가렸다. 최종 화면은 최신 한 장, 16px 본문과 44px 공감 버튼을 사용한다. 짧은 화면은 테이블 여백에 배치하고 입력·흡연 동작 중 감춘다. 카드 글 부분은 뒤의 물건 클릭을 통과시키며 공감 버튼만 입력을 받는다. 320px에서 실제 손 위치를 눌러 한 모금이 시작되는 것을 확인했다.
- 직접 입력과 정형 문구의 공용 상한, 다른 방 차단, 중복/변경된 요청, 3초 간격, 교체한 카드의 과거 요청 재시도, 재접속·휴면 복구 후 중복 방지, 실제 45초 만료·개인 저장 실패 중 삭제를 검사했다. 독립 검수에서는 응답 중 새 초안 보존, HTML 리터럴 표시, 마지막 10초 페이드와 다른 상태 갱신 시 잔여 수명 유지도 확인했다.
- 중앙 네 자리·창가 두 자리와 출입구의 모든 경로가 공유 장애물을 통과하지 않았다. 옛 배치의 좌석 예약과 이동 중 저장 상태를 복원하는 검사를 추가했다. 두 브라우저에서 내 손과 맞은편 동료의 들기·내쉬기·재털기·직접 끄기를 확인했다. 종이 길이·재 길이·재떨이 접촉은 같은 서버 시각을 사용한다. 일곱 모금 뒤 새 담배, 이동 중단과 동작 감소도 독립 검수했다.

## 착석 시선과 흡연실 (2026-11-09)

- 1인칭 통합본은 390px에서 방향키와 터치 드래그 후에도 좌석, 눈높이와 위치가 같고 시선만 바뀌었다.

- 390px에서 사용자가 동작 줄이기를 켜고 머신으로 걸었을 때 광축을 유지했고, 수동 회전과 컵 놓기가 동작했다. 컵 선반과 머신을 직접 클릭해 추출한 뒤, 테라스 출입문을 양방향으로 클릭해 원래 6번 자리로 복귀했다.
- 두 브라우저에서 익명 한마디와 공감을 교환하고 재접속 후 상태를 확인했다. 연결을 끊은 탭에서도 만료 후 카드가 사라졌다. 6명이 이용하는 세로 화면에서 한마디와 이름표의 겹침을 검사했다. 568×320 가로 화면에서 네 문구 중심을 모두 터치할 수 있었다.
- 390px 고정 시점에서 빈 창틀, 황토색 리본 한 가닥, 청록색 리본이 겹쳐진 모습을 차례로 캡처했다. 공감과 한마디는 접속한 두 사람이 각각 눌렀다. 동작 줄이기 상태에서도 두 색과 윤곽을 볼 수 있다. 이름표는 리본을 가릴 때만 숨긴다.
- 390px에서 WebGL을 끈 두 방문자가 2D 화면으로 흡연실에 모여 한마디와 공감을 주고받았다. 탕비실 복귀와 힐링방 왕복 중 3D 초기화 재시도는 없었다.
- 냉장고 손잡이를 직접 누른 뒤 1280×720 화면에서 문을 열고 위 선반의 병을 눌러 가져왔다. 320×568에서는 제보된 (136, 284) 위치의 화분을 연달아 터치해서 분무기를 집고 물을 뿌렸다.
- 첫 진입 JS를 2.5초 지연했을 때 초기 HTML이 게임 배경색과 ‘탕비실을 여는 중…’ 상태를 표시했고, React가 입장 화면을 그리면 대기 문구가 사라졌다.
- 모바일 크기는 자동화한 브라우저 뷰포트다. 실물폰에서 손으로 조작할 때의 피로와 프레임 속도는 별도 사용성 검수가 필요하다.

## 전체 코드 점검·자원 및 연결 최적화 (2026-11-06, 로컬 검수)

화면 후보는 UTC 14:08:12 빌드 `index-cT2ZeZzy.js`·`Room3D-DDPdzm39.js`로 고정했다. 이후 서버의 저장 실패 중 퇴장 처리만 보완했다. 새 기능·유료 구성·의존성 업그레이드는 추가하지 않았다. 기존 SDK는 구버전 코드의 참조가 남아 있으나 현재 진입 번들에 포함되지 않아 무작정 삭제하거나 번들 축소로 보고하지 않는다.

- **그래픽 자원:** 병 라벨의 동일한 텍스트·색·글꼴은 재질과 텍스처를 재사용한다. 독립 검토자의 실제 3병 반복 음용에서 살아 있는 WebGL 텍스처가 기존 58→71로 늘던 현상이 수정본에서는 46개로 유지됐고 페이지 오류는 0이었다. 60회 생성·해제 자동 검사도 텍스처 1개·해제 후 기하 0개를 확인한다. 커피 단계만 바뀔 때 트레이 전체를 다시 만들던 키도 제거했다. 음료 잔량처럼 외형이 달라지는 경우의 모델 재생성은 유지하므로 모든 GPU 업로드가 없어졌다는 뜻은 아니다.
- **음원 준비:** 파도 전용 모드는 파도 파일 1개만 요청한다. 독립 브라우저 검사에서 기존 17개 요청 중 효과음 16개, 1,335,168bytes를 생략했다. 효과음을 켜면 준비하고 이미 성공한 파일은 다시 받지 않으며 실패한 파일만 재시도한다. 이는 로딩 검사이며 직접 청취 평가는 아니다.
- **공용 상태 조회:** 한 번의 방송에서 공간별 공개 멤버만 캐시하고 개인 소지품·기록·시식 여부는 수신자별로 유지했다. 독립 검토의 6명×100개 간식 이력에서 SQL 읽기 138→48회, 최신 간식 조회 42→12회였다. 추가 인덱스의 조회 계획이 전체 스캔/임시 정렬 대신 인덱스를 사용하는 것을 검사했다. 두 방문자 개인 상태 격리와 힐링방 분리도 유지한다.

## Cloudflare 무료 경로 이식
공통 저장·생활 오브젝트·이동·간식 검증/스냅샷 규칙을 Node와 DO에서 함께 사용한다. Node DB·4317 실행은 보존하고 별도 Cloudflare 저장소로 검사했다. 기존 Pages와 유료 서비스에는 배포하지 않았다.

- **DO 런타임:** Miniflare의 실제 SQLite DO·휴면 WebSocket에서 두 독립 방문자가 포장/나눔/수령/맛봄을 수행했다. `unsafeEvictDurableObject(..., webSockets:'hibernate')`로 휴면시킨 뒤 같은 연결의 ping·행동·커피 완료 알람을 확인했다. 방문자 객체도 재생성했다.
- **방 사이 시식:** B가 window에서 받은 조각을 들고 breeze로 이동 → 연결 종료/새로 연결 → 먹기 → A는 quiet로 이동 → B가 window 복귀했다. 조각 ID·개인 발견/예산 50·원래 접시 claimed/tasted=1을 확인했다. 초기 시식 외래키 오류를 재현해 DO의 방간 참조로 수정했으며 Node의 외래키는 유지한다.
- **장애/동시성:** 개인 저장 직전 권한 버전을 어긋나게 한 장애 주입에서 503을 받은 뒤 복구·동일 요청 재시도로 한입 1회·예산 50만 반영됐다. 같은 방문자의 두 연결에서 동시에 같은 요청을 보내도 개인 간식은 1개다. 방 쓰기 권한만 남긴 입장 중단도 다른 방 이동 시 복구한다.
- **생활/개인 상태:** 실제 이동 시간·자리/머신 동시 점유 거절, 휴면 중 커피 추출 완료·가져오기, 냉장고 열기/병/닫기, 힐링방 진입, 모래 선·꽃 배치, 기존 42% 포장·병 한 모금을 방 이동 뒤 복구했다. 개인 모래 표면은 동료 공개 상태에 없다.
- **제한:** 6명 입장·7번째 409, 허용되지 않은 방 404, 설정한 일일 한도 429를 실제 런타임에서 확인했다. 배포는 Free 계정 확인이 별도로 필요하며 로컬 검사는 요금/부하를 증명하지 않는다.
- **미디어:** 실제 Workers Assets에서 빠진 Content-Length 때문에 영상이 416으로 실패하는 것을 브라우저에서 재현·수정했다. 빌드 크기 목록을 적용한 MP4 0–1바이트는 206/2바이트이고 영상 readyState=4·재생 시간 진행을 확인했다. 범위/suffix/HEAD/잘못된 범위/If-Range/크기 헤더 없음의 자동 검사를 포함한다.
- **실제 화면:** 로컬 CF의 독립 A(390/320px 터치 Chromium)·B(1280px)에서 나눔 → 시식 → 먹기 → 새로고침 후 shared 발견·빈 접시·예산 50을 확인했다. 파도 켜기 뒤 WAV 요청과 WebAudio 시작을 계측했고 끄기 버튼을 실행했다. 320px에서 가로 넘침이 없었다. 만원 안내의 작은 화면 검수는 409 응답을 고정한 화면 검사이며, 실제 정원 검사는 별도 DO 테스트다.

로컬 증거는 `test-results/cf-mobile-320.png`, `cf-mobile-390.png`, `cf-full-320.png`와 CF 자동 검사다. 간식 캡처는 지연 로딩이 끝나 실제 접시·음식·동료가 보이는 상태로 갱신했다. 공개 HTTPS 결과와 남은 검수는 위 절에 구분했다. 청취감이나 동접 수를 수치 검사로 단정하지 않는다.

## 최신 빌드: 모래 반응·실녹음·동료 동작·꽃병
기존 DB를 초기화하지 않고 독립 방문자 A(1280×720)·B(터치 Chromium 390×844, 320×568)로 실행했다. 차 준비 → 힐링방 → 모래 → 내려놓기 → 복귀를 수행하고, 모래/꽃병의 교체·중단·재집기를 확인했다.

- **직접 입력:** 긴 획이 64점씩 두 번 저장되어 모두 200을 받았다. 앞선 선을 단순화하지 않고 이어 그린 결과와 청크 저장 결과가 같은 자동 검사도 통과했다. 물체 swipe/꽃병 방향키 전후 카메라 좌표·yaw/pitch는 같았고 방 swipe/방향키만 시선을 바꿨다. 이동 중 선택한 시선이 착석 후 유지되는 카메라 검사 5개도 유지했다.
- **크기:** 320×568/390×844 실제 방 캔버스 높이는 394/670px, 가로 넘침 없음. 모래 주 행동·다듬기·내려놓기는 44px 높이였다. 최종 캡처는 입력/저장과 화면 갱신이 끝난 뒤 촬영했다.
- **소리 계측:** 기본 무음·씹는 소리 끄기, 파도만 상태의 모래 소스 시작 0회, 파도와 행동 상태의 짧은 변주를 관측했다. 드래그 7회 시작의 rate는 약 0.970, release 시 남은 소스에 약 40ms fade/45ms stop이 예약됐다. Enter/Space도 각 0.3초 클립을 재생한다. 모래 입력 중단/비활성/공간 전환/연결 종료 정리와 동료 contact 종료를 확인했다. 원음 4개 편집의 PCM 끝 샘플 0·클리핑 0, 모래 peak -23dBFS/돌 -26dBFS를 확인했다. 이는 청취 평가가 아니다.
- **개인 꽃병:** 실제 선반 접근, 세 꽃 중 선택, 줄기/꽃잎 드래그와 탭·방향키·버튼, 내려놓기와 재집기. 위치·기울기·꽃 선택은 왕복/새로고침 후 유지되며 다른 방문자의 꽃병을 덮어쓸 수 없다. 모래→꽃병→놓기, 꽃병→모래→놓기 양방향에서 마지막 도구가 주 버튼으로 복구되고 새로고침에도 남는다. 독립 검토 채팅도 같은 결과를 확인했다.
- **동료:** 한 명 단독, 두 독립 브라우저, 여섯 인증 연결 상태를 구분했다. 6명 검사는 두 실제 화면과 추가 4개 SSE 방문자로 수행했으며 6명이 동시에 조작한 사용자 시험은 아니다. 여섯 자리가 각각 예약되고 현재 방 인원 6, 이미 점유된 자리 요청 409를 확인했다. 가까운 동료의 걷기/착석·짧은 모래 손동작·잔 들기를 촬영했다. 기본 손은 무릎으로 내리고, 잔을 입 아래로 가져가도록 팔 도달점을 고쳤다. 뒷사람 이름이 앞사람 이름처럼 겹치는 경우를 숨기고 가까운 이름을 우선한다.
- **공개 범위:** 모래 공개 값은 held/revision/changedAt/changedKind, 꽃병은 flower/held뿐이다. 선/돌/꽃 배치/개인 ID는 다른 방문자의 스냅샷에 없다. 입력 종료 뒤 contact=null이며 지연 패킷이 동작을 되살리지 못한다. 다른 방의 동료는 렌더링/소리 대상에서 빠진다.
- **기존 흐름:** 이동 중 멈추기→재출발, 두 방문자 동시 출입의 서로 다른 자리, 도구 자동 보관을 확인했다. B의 차 0.233666…와 모래 revision 2는 왕복 후 같았고, 이후 직접 마시는 행동에서만 차 양이 줄었다. 기존 시식 받기→먹기 후 empty/나눔 버튼 0개, 추가 offer 요청 409를 재확인했다. 독립 검수는 42% 부분 개봉과 꽃·차·모래의 복구도 확인했다.

### 독립 검수 후 보완 (같은 로컬 CF, 공개 배포 전)
- 첫 착석에서는 간식 안내만, 일어난 뒤에는 바닥 이동 안내를 표시한다. 390×844의 새 두 번째 방문자에서 첫 간식 안내가 나타난 첫 15개 프레임 모두 실제 좌석 1의 눈 위치 (-0.9645, 1.6230, 1.6550)를 유지했다. 입장 전 임시 좌석 0에서 테이블을 가로질러 카메라를 보간하지 않는다. 390×844·320×568에서 포장 전체와 안내가 보이고 가로 넘침이 없다. 앉은 채 터치 드래그로 시선은 바뀌고 좌표는 유지됐다. 안내는 하단 조작과 충돌하면 숨기며, 화면 밖 간식에 잘못된 화살표를 붙이지 않는다.
- 390px 실제 터치 동선: 좌석 0→6에 착석→뒤쪽 빈 바닥 탭으로 (-2.034, 4.358)까지 보행→커피 머신→돌아가기에서 좌석 6 복구. 이어 좌석 6→7→일어나기→커피 머신→돌아가기에서 좌석 7 복구. 이동 중 예약된 좌석을 마지막 쉰 자리로 덮어쓰지 않는다. 좌석 번호는 내부 0 기준이며 UI에서는 각각 1·7·8번이다.
- 나눔 접시 옆 작은 버튼과 메뉴의 대체 동작을 복원했다. 320px 독립 방문자가 메뉴에 키보드 Enter로 진입→Tab으로 ‘동료가 나눈 한 조각 맛보기’에 초점→Enter로 받기→키보드 한입 먹기로 bites 0→1, 오류 안내 0을 확인했다. 하단 패널은 추가하지 않았다.
