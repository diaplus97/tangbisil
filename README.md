# 탕비실 · 바다 앞에서 잠깐 쉬기

같은 방에서 말없이 쉬고, 간식과 음료를 준비하는 웹게임입니다. 내 시점은 넓은 1인칭이며 **앉아 있어도 드래그·터치·방향키로 주변을 둘러봅니다.** 메인 방에는 테이블 3개·의자 8개, 힐링방에는 빈백 4자리·창가 2자리가 있고 두 공간을 합쳐 6명까지 함께합니다. 로컬 Node 실행과 Cloudflare 무료 테스트 배포 구성을 지원합니다.

## 실행
Windows에서 **탕비실 실행.cmd**를 더블클릭하면 `http://127.0.0.1:4317`이 열립니다. 이미 실행 중이면 같은 서버를 사용합니다. 이 작업 폴더에는 빌드와 의존성이 준비되어 있습니다.

새로 받은 저장소에서는 Node.js 24 이상으로:

```sh
npm ci
npm run build
npm start
```

개발 중에는 `npm run dev`를 사용합니다. pnpm은 `pnpm install --frozen-lockfile` 후 같은 스크립트를 실행합니다. 현재 확인 명령은 `npm run typecheck`, `npm test`, `npm run build`입니다.

## 잠깐 쉬어보기
1. 이름은 선택입니다. **앉아서 쉬기**로 입장합니다.
2. **간식 꺼내기 → 포장 열기 → 한입 먹기.** 포장은 오른쪽으로 당겨도 됩니다. 내려놓고 다시 집거나 새로고침해도 부분 개봉·남은 모양·기록이 이어집니다.
3. 열린 간식은 먹기 전에도 **한 조각 나누기**로 내놓습니다. 동료는 **한 조각 맛보기 → 한입 먹기**로 받으며 제공자의 개인 음식은 줄지 않습니다.
4. **둘러보기**에서 사물과 자리를 선택하거나 화면 속 사물·빈 의자를 직접 누릅니다. 드래그는 시선만 바꿉니다. **바다 보기** 또는 Home으로 창을 바라보며, 이동 중에도 멈추거나 목적지를 바꿀 수 있습니다.
5. **내려둔 물건**에서 같은 물건을 다시 집습니다. 손에 다른 것이 있으면 내려놓고 바꿔 집는다는 문구가 먼저 보입니다. 작은 화면의 목록은 방 위에 열리고 닫기 버튼으로 닫습니다.
6. **메뉴 → 기록**에서 날짜와 출처를 확인합니다. **동료 초대**로 같은 방 링크를 복사하거나 **이용 안내 → 두 번째 방문자 열기**로 독립 방문자를 시험합니다.

| 가 볼 곳 | 할 수 있는 일 |
| --- | --- |
| 힐링방 | 오른쪽 문 또는 둘러보기 → 문까지 걸어 입장 → 빈백/창가에서 쉬기 → 탕비실로 돌아가기 |
| 모래 트레이 | 힐링방 선반에서 가져오기 → 자리에서 선 긋기·돌 옮기기·표면 고르기 → 내려놓기·재집기 |
| 한 송이 꽃 선반 | 힐링방에서 꽃 고르기 → 자리에 앉아 줄기 위치/꽃 기울기 조절 → 내려놓고 쉬기 |
| 사탕 그릇 | 하나 집기 → 한 번 눌러 포장 열기 → 먹기 |
| 커피 머신 | 내 컵 놓기 → 추출 → 가져오기. 중간에 떠나면 추출을 멈추고 컵 반환 |
| 냉장고 | 문 열기 → 한 병 꺼내기 → 닫기. 떠나면 자동 닫기 |
| 창가 식물 | 분무기 집기 → 한 번 뿌리기 → 내려놓기. 시듦·관리 점수 없음 |
| 손놀이 바구니 | 말랑돌 집기 → 편한 자리 → 원하는 곳 톡 누르기 → 천천히 복원. 내려놓기·재집기·반납 |
| 차 트레이 | 내 찻잔 놓기 → 티백 → 물 붓기/멈추기 → 티백 받침 → 잔 가져오기. 중간에도 가져가기 가능 |

모래 위를 끌면 갈퀴 홈이 생깁니다. 돌은 끌거나 돌과 놓을 곳을 차례로 누릅니다. ‘선 한 번 긋기’와 ‘모래 다듬기’의 버튼도 사용할 수 있습니다. 모래는 개인 상태이며 나갈 때 힐링방에 보관됩니다. 다시 들어오면 같은 선과 돌이 남습니다. 꽃병의 꽃 선택·위치·기울기도 보관됩니다. 꽃잎과 줄기를 각각 밀거나 눌러 조절하고, 방향키/꽃 자리 조절 버튼으로도 움직입니다. 마지막으로 내려놓은 모래나 꽃병은 주 버튼으로 다시 집습니다. 차·음료·먹던 간식은 두 공간에서 이어지고 새 간식/공용 시식은 탕비실에서 준비합니다.

간식은 방 앞의 접시로 나타납니다. 내 몸은 내 화면에서만 숨기며 동료에게는 아바타와 행동이 보입니다. 16 × 14.4m 방의 중앙·바다 앞·조용한 쪽 자리를 선택합니다. 모든 동료가 항상 한 화면에 보이는 구성은 아닙니다.

## 풍경과 소리
**기본은 무음**입니다. 소리 켜기로 조작 소리를, **파도 소리 켜기/끄기**로 환경음을 따로 선택합니다. 메뉴의 소리·풍경 설정에서 무음·파도만·파도와 행동, 전체/파도 음량, 동료 소리, 개인 씹는 소리, 바다 움직임을 고릅니다. 씹는 소리는 기본 꺼짐입니다.

창밖은 생성 원경의 수면을 움직인 24초 WebM/MP4 시네마그래프이며 실사 촬영 영상이나 GIF는 아닙니다. 동작 감소 기기에서는 정지로 시작하고 비활성 탭·화면 밖·모달에서는 멈춥니다. 영상 재생이 실패하면 정지 풍경으로 이어집니다. 파도와 조작 소리는 CC0 공개 녹음의 HQ MP3 미리보기를 편집했습니다. [풍경 제작 기록](docs/LANDSCAPE_ASSET.md)과 자산 폴더의 제작자·라이선스·편집/해시를 보존합니다. 모래 마찰과 돌 접촉음도 실제 녹음으로 추가했습니다. 손을 떼면 짧게 잦아들고 멈춥니다. 수치/재생 시점 검사는 마쳤으며 헤드폰 청취 평가는 남아 있습니다.

## 범위와 개발 문서
구현된 흐름은 개인 물건 저장, 공용 시식, 수령/맛봄 구분, 소유권·중복 요청 검사, 첫 발견 기록/예산, 이동·점유 동기화입니다. 일반실에는 대화가 없습니다. 힐링방·개인 모래 트레이·작은 개인 꽃병까지 연결했습니다. 흡연실 내부·사념/내쉬기·추가 피젯/ASMR·간식 풀 운영은 후속 범위입니다.

- [현재 개발 기준](docs/DEVELOPMENT.md): 결정·구조·다음 작업·구버전 운영 주의
- [검증 상태](docs/QA.md): 실행 증거·자동 검사·미검증 기기/사용성
- [필코노미 원칙](docs/FEELCONOMY.md): 설계 근거와 연구의 한계
- [풍경 자산 기록](docs/LANDSCAPE_ASSET.md): 원본·생성/편집·출처

일반 화면에는 시점/조명 비교 메뉴가 없습니다. `?dev=1&view=3d&camera=map`은 전체 보기, `camera=third`는 이전 낮은 3인칭입니다. 메인 방의 `?view=pixel`과 WebGL 실패 시 도트 복귀를 유지합니다. 힐링방은 3D 전용이며 화면을 열지 못하면 탕비실로 돌아갈 수 있습니다.

## 저장과 접속
`data/pantry.sqlite`에 개인 음식·컵/병·말랑돌/차/모래·머문 공간·앨범·예산·시식을 저장합니다. 서버 재시작/긴 이탈 시 자리는 재배정될 수 있지만 확인된 물건과 기록은 유지됩니다. `data/`는 Git에서 제외합니다.

방문자 토큰은 브라우저에, 서버에는 해시만 보관합니다. 브라우저 데이터를 지우면 이전 방문자로 돌아갈 수 없으며 계정 복구·기기 간 동기화는 아직 없습니다. 실행 중 DB를 백업할 때는 SQLite WAL을 고려하거나 먼저 서버를 종료해야 합니다.

같은 네트워크의 다른 PC와 시험하려면 별도 PowerShell에서:

```powershell
$env:HOST = '0.0.0.0'
$env:PORT = '4318'
npm start
```

다른 PC는 호스트 PC의 LAN 주소로 접속하며 포트 접근이 허용되어 있어야 합니다. 휴대폰의 UUID·클립보드 기능까지 시험하려면 아래 HTTPS 배포 주소를 사용합니다. 이전 Cloudflare Pages 정적 배포만으로 현재 Node/SQLite/SSE API가 실행되지는 않습니다.

## Cloudflare 무료 테스트 배포
[공개 탕비실 열기](https://tangbisil-playtest.diaplus93.workers.dev/?room=window). 2026-11-06 Workers Free로 배포했으며, 같은 주소를 PC와 휴대폰에서 열어 함께 입장할 수 있다. 공개 HTTPS에서 독립 방문자 두 명의 간식 나눔·맛봄·새로고침 후 기록 복구, 사탕·커피·냉장고 동기화와 바다 영상 재생을 확인했다. 320/390px 화면은 브라우저에서 검사했으며 실제 휴대폰·Safari·청취 검사는 아직 남아 있다. 자세한 증거와 한계는 [QA](docs/QA.md)를 따른다.

현재 공개 테스트 경로는 **Workers Static Assets + SQLite Durable Objects**다. 기존 `wrangler.toml`은 구 Pages용이므로 사용하지 않는다. 새 `wrangler.pantry.jsonc`는 별도 Worker **`tangbisil-playtest`**를 대상으로 하며 기존 Pages를 덮어쓰지 않는다. 로컬 Node/SQLite/SSE 실행은 그대로 유지한다.

```sh
npm ci
npm run build:cloudflare
npm run test:cloudflare
npm run dev:cloudflare
```

로컬 Cloudflare 주소는 `http://127.0.0.1:8787`, 별도 개발 DB는 `data/cloudflare`다. Node의 `data/pantry.sqlite`를 업로드하거나 변경하지 않는다. Wrangler **4.156.2**를 두 잠금 파일에 고정했다. 검사 명령은 로컬 런타임과 `--dry-run`만 사용한다. 배포 담당은 계정의 **Workers Free** 표시를 확인한 뒤 `npx wrangler deploy --config wrangler.pantry.jsonc`로 새 Worker를 배포하고 출력된 HTTPS 주소에서 두 방문자를 검수한다. 유료 전환이나 별도 유료 서비스 생성은 이 구성에 없다. 비용이 필요한 변경은 먼저 사용자에게 알린다.

무료 계정에서는 `limits.cpu_ms` 설정이 배포 오류 100328로 거절된다. 사용자 지정 CPU 제한을 넣지 않고 Workers Free의 기본 제한을 사용한다.

| 저장/연결 | 역할 |
| --- | --- |
| `PantryRoom` | 방마다 1개, 두 공간 합계 6명. 자리·가구·나눔/수령/맛봄·행동 순서와 저장 대기 기록 |
| `PantryVisitor` | 방문자마다 1개. 음식·음료·개인 도구·기록·재시도 영수증과 방 쓰기 권한/버전 |
| `PantryGate` | 고정 8개로 입장 제한 분산. IP 원문 대신 해시와 당일 카운터만 보관 |
| WebSocket | 휴면 지원 연결. 자동 ping 응답, 영속 연결 첨부정보로 복원. 서버의 반복 타이머/SSE 없음 |
| Alarm | 이동·추출/붓기 완료, 연결 종료 유예, 실패 저장의 제한된 재시도에만 사용 |

개인 상태는 방 객체의 SQL 트랜잭션과 저장 대기 기록을 함께 확정한 뒤 방문자 객체에 버전 순서대로 반영한다. 확인된 다음에만 화면에 성공을 알린다. 중간 실패는 같은 요청으로 이어가며 개인 기록의 새 방 이동은 이전 방 저장/권한 반환 후에만 허용된다. **같은 방문자를 다른 방 링크에서 열면 이전 방 화면은 쉬는 상태로 전환**된다. 같은 방은 두 화면까지 허용한다. 시식을 들고 다른 방으로 가도 개인 조각은 유지하며, 먹었다는 알림은 원래 방의 접시에 중복 없이 전달한다. 다른 방 DB의 접시를 직접 참조하는 외래키는 사용하지 않는다. Node에서는 기존 단일 DB 외래키를 유지한다.

무료 검증 설정은 허용 방 `window,breeze,quiet,sunset`만 열고 임의 방 이름 생성을 거절한다. 방마다 하루 행동/접촉 메시지 **2,000개**, 방문자당 초당 **8개** 제한이며 만원/당일 한도에서는 자동 재접속을 멈추고 다시 연결·다른 방 선택을 보여준다. 입장 제한은 샤드별 신규 방문자 64명/일·연결 요청 800개/일, IP별 신규 6명/일·연결 요청 240개/일·12개/분이다. 연결 준비와 WebSocket 업그레이드는 각각 한 요청이다. 카운터는 UTC 날짜를 기준으로 바뀐다. `ADMISSIONS=closed`로 새 입장을 멈출 수 있다. 이 값은 초기 공개 검증용 제한이며 동접 성능이나 월 청구액의 절대 상한을 뜻하지 않는다.

2026-11-06 기준 [Workers Free](https://developers.cloudflare.com/workers/platform/pricing/)는 Worker 요청 100,000회/일, [DO Free](https://developers.cloudflare.com/durable-objects/platform/pricing/)는 요청 100,000회/일·13,000 GB-s/일·SQL 읽기 500만 행/일·쓰기 10만 행/일·총 저장 5GB 한도다. Free 한도 초과는 해당 작업의 제한으로 이어지며 유료로 자동 전환하는 코드는 없다. 서비스 카운터 외에도 인증·알람·DB 복구 등이 한도를 소비하므로 남은 무료 사용량은 운영 대시보드에서 확인한다. 실제 부하검사 전 지원 동접과 월요금을 단정하지 않는다.

일반 [정적 자산 요청은 무료](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)이며 API와 바다 영상 경로만 Worker를 거친다. 영상의 Range 요청은 빌드 시 만든 크기 목록으로 206/416·HEAD·suffix를 처리한다. 일부 Static Assets 응답에 `Content-Length`가 없어도 Safari의 MP4 탐색 요청이 동작한다. 영상 요청은 Worker 사용량에 포함된다. 빌드는 파일당 25MiB 제한을 검사하고 자산 출처를 `/credits`에 복사한다. 실제 iPhone Safari 검수는 별도다.

공개 배포의 health·두 방문자 나눔·새로고침 검수를 마쳤다. 시식을 든 방 이동/맛봄은 로컬 DO에서 검증했으며 공개 환경의 방 이동·재배포 후 개인 기록은 후속 검수 대상이다. 방문자 토큰은 해당 브라우저에 있으므로 PC 기록이 휴대폰으로 자동 이전되지는 않는다. 로컬 실행과 다른 주소에서는 새 방문자로 시작한다. 계정 복구·대규모 부하·운영 백업/보존 정책도 후속 검토 대상이다.

선택 배포용 Docker와 `render.yaml`은 유지한다. Node 24 단일 서버, `HOST=0.0.0.0`, 플랫폼 `PORT`, `/api/health`, 영속 DB 경로가 필요하다. Render는 `/var/data/pantry.sqlite`와 1GB 디스크, Railway는 `/data/pantry.sqlite`와 해당 볼륨을 사용한다. 유료 서비스 생성은 보류한다. `npm run check:runtime`은 별도 임시 폴더/DB에서 Node 배포 구성을 검사한다. 구 Cloudflare용 `verify:deploy`·`verify:online`은 실행하지 않는다.
